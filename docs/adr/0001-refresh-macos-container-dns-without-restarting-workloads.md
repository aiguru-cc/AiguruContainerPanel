# ADR-0001：不重启工作负载地刷新 macOS Container DNS

- 状态：已采纳
- 日期：2026-08-25
- 决策范围：应用集群、Apple Container DNS、macOS 本机解析

## 背景

Apple Container 容器重建后可以继续正常运行，但 macOS 可能仍保留旧的 `.local` 解析结果，或 Container CLI 的 DNS 转发注册状态未及时更新。此时通过已发布的 `localhost` 端口可以访问服务，而通过容器 DNS 名称访问失败。

这类故障发生在宿主机解析与转发层，不应通过停止、重建容器或删除网络处理。上述操作会影响正在运行的工作负载，也不能保证清除 macOS 的解析状态。

## 决策

在应用集群的网络概览中提供“强制刷新 DNS”操作，并遵循以下顺序：

1. 使用当前工作环境对应的 Container CLI 查询已注册的 DNS 转发域。
2. 当查询结果为空时，仅以 Apple Container 默认的 `local` 域作为恢复目标。
3. 经用户确认和 macOS 管理员授权后，依次删除并重新创建目标 DNS 转发域。
4. 执行 `dscacheutil -flushcache` 清理系统 DNS 缓存。
5. 向 `mDNSResponder` 发送 `HUP`，使本机名称解析服务重新加载。
6. 刷新应用内的容器状态，并明确显示执行进度和结果。

## 安全与边界

- 刷新流程不得停止、删除、重启或重建容器。
- 刷新流程不得删除或重建容器网络、卷及镜像。
- 必须使用当前选定工作环境的 CLI 路径，避免操作其他工作环境。
- 需要提权的固定命令通过 macOS 标准管理员授权执行，不保存管理员凭据。
- CLI 路径和域名必须进行 shell 与 AppleScript 转义，禁止把未经处理的动态文本拼入提权命令。
- 删除 DNS 转发域允许幂等失败，但重新创建、系统缓存刷新或 mDNS 刷新失败必须向用户报告。

## 结果

该操作可修复“容器运行正常、端口访问正常，但重建后的 `.local` 名称不可解析”的宿主机状态，同时不扰动现有工作负载。执行期间 DNS 名称可能出现短暂不可用，完成后应用会重新探查当前工作环境中的容器状态。

## 未采用方案

- 重启或重建容器：故障不在容器进程层，并会中断业务。
- 删除并重建容器网络：影响范围过大，且不能可靠清除 macOS 缓存。
- 只刷新 `mDNSResponder`：无法修复 Container CLI DNS 转发注册本身的陈旧状态。
- 自动静默提权：缺少清晰的用户授权与操作反馈，不符合安全边界。

## 后续约束

若未来 Container CLI 更改 DNS 管理指令，应通过版本化命令目录适配，不得在视图中新增另一套未归版的命令语义。若 Apple 提供无需重注册即可原子刷新的官方接口，应优先迁移，并保留上述不影响容器工作负载的原则。
